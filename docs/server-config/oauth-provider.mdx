---
title: "Use Your Identity Provider"
description: "Accept access tokens from your OAuth or OpenID Connect provider. All SQL runs as one service account."
---

At the end of this page, people sign in with your company login and the server accepts their access tokens. The server only checks tokens. Your provider handles sign-in.

<Warning>
**Every person's SQL runs as the `DB2i_USER` service account.** The token says who is calling, but it is never passed to the IBM i. Give that profile only the authority everyone who can sign in may use. To run SQL as each person, use [IBM i sign-on](/server-config/oauth-ibmi-signon) instead.
</Warning>

## What you need

- An OAuth 2.1 or OpenID Connect provider that issues **JWT** access tokens signed with an asymmetric algorithm (RS256, ES256, EdDSA, …).
- A service account profile on the IBM i for the server.
- HTTPS in front of the server: a reverse proxy, or the server's own certificate (`MCP_TLS_CERT_FILE`, `MCP_TLS_KEY_FILE`).

## Set it up

<Steps>
  <Step title="Configure the provider">
    - Register the MCP server as an API (resource) with the identifier `https://mcp.example.com/mcp`, so tokens carry it in `aud`.
    - Optionally define a scope such as `mcp:tools`, and grant it to the people allowed to use the server.
    - Turn on a client registration method your MCP clients support (dynamic registration or Client ID Metadata Documents).
  </Step>

  <Step title="Find the issuer">
    ```bash
    curl -s https://auth.example.com/.well-known/openid-configuration | jq .issuer
    ```

    Copy the value exactly, including any trailing slash.
  </Step>

  <Step title="Configure and start the server">
    ```bash
    MCP_TRANSPORT_TYPE=http
    MCP_AUTH_MODE=oauth
    MCP_RESOURCE_URL=https://mcp.example.com/mcp
    MCP_ALLOWED_HOSTS=mcp.example.com
    OAUTH_ISSUER_URL=https://auth.example.com
    OAUTH_REQUIRED_SCOPES=mcp:tools        # optional

    DB2i_HOST=ibmi.example.com
    DB2i_USER=MCPSVC
    DB2i_PASS=...
    ```

    Behind a proxy, also set `MCP_TRUSTED_PROXIES` to its address. If the provider can't put the resource URL in `aud`, set `OAUTH_AUDIENCE` to the value it uses.

    The log shows `OAuth authentication enabled.`
  </Step>

  <Step title="Check it works">
    Without a token, the server answers with a challenge that points clients to your provider:

    ```bash
    curl -i -X POST https://mcp.example.com/mcp \
      -H "Content-Type: application/json" \
      -H "Accept: application/json, text/event-stream" \
      -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
    ```

    Expect `401 Unauthorized` with a `WWW-Authenticate: Bearer … resource_metadata="…"` header. Then add `https://mcp.example.com/mcp` to an [MCP client](/clients/overview). It opens your provider's sign-in page on first use.
  </Step>
</Steps>

## Good to know

- **JWT access tokens only.** Opaque tokens and token introspection are not supported.
- **One provider per server**, and scopes apply to the whole server, not per tool.
- **Clocks must agree.** The server allows no clock skew when it checks a token's expiry.
